# 产品、教学与 AgentArts 开发任务书

你负责教学规则、教学样例和两段比赛工作流。应用团队负责状态和正式发布。你的输出会被应用执行结构与来源校验，再进入学习图或当前节点。先用 [共用开发契约](01-contract.md)、[联调样例](examples.json)和[自编短教材](fixtures/network-mini-textbook.md)验证两个小流程，再换成长教材与第二个示例领域。

## T1 · 先让两段真实工作流可调用

两段流程用已有输入快照和样例跑通。查个人记录和公开来源的工具按 [T4 的共用工具契约](06-agent-tools.md)并行接入。

1. 建两个可发布工作流 `textbook_plan` 与 `resume_branch`。使用开始节点接收 `payload_json`，先校验并解析，再执行教学步骤，结束节点输出单个 `result_json`。不要在 JSON 外带解释文本。格式化错误用可读 `issues` 返回。应用侧与平台侧都保留同一个 `request_id`。
2. 在工作流调试里分别导入样例的 `workflows.textbook_plan.request`、`workflows.resume_branch.request`。切换续学里的 `alternate` 继续验证。逐步检查实际读到的输入、所用原文、最后的结构和运行耗时。
3. 为实际调用创建并发布部署。把控制台生成的调用示例中与本部署有关的端点、认证形式、变量和响应提取路径做成可读模板，提供环境配置指引。需要流式读取时，与后端约定怎样拼接终态 JSON。先用模板完成一次应用外请求，再从应用 job 接一次。
4. 将可导出的流程定义、受控提示词、参数样例和恢复部署的步骤放在 `agentarts/`。运行记录写所用流程/部署标识、输入版本、响应和用时，处理好测试内容与凭据。后端能用同一输入切换 mock 与真实调用。

平台操作依据 [工作流发布与部署](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0053.html)、[API 调用](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0055.html)、[调用已发布工作流的输入参数](https://support.huaweicloud.com/bestpractice-agentarts/agentarts_06_0022.html)。

## T2 · 教材编排与验收工作流

| 步骤 | 实现与中间产物 | 验收 |
| --- | --- | --- |
| 固定编排任务 | 接教材版次、已确认的范围、目标、学习时限、考核材料和旧节点。验证目录、范围单元、页/节定位齐全。教材内容按教学数据使用。 | 能复述本次学习目标、范围与考查来源。缺影响理解的材料时给补件清单。 |
| 分组分析 | 按目录分组跑短上下文子任务，抽取本组概念、适用条件、必读页、图表、例题、练习候选和潜在前置。保存可回查的候选单元与章级摘要。 | 每个原节有分析结果，跨组引用从原文或已有定义取得，缺组可定位并重做。 |
| 全局编排 | 基于各组产物跨节重组。给每个节点一组可观察目标、引入、阅读步骤、知识点、出处和对齐目标的练习。输出全书路线、核心路线和适用的限时安排。 | 能解释重组如何改善学习，必要前置和推荐先后有独立表示，无前置的节点可并列。 |
| 独立核查 | 另用一个校验过程按范围逐节查漏，沿真实任务验证前置理由，逐题先解题再对照参考解和目标，检查条件、歧义与所需范围。 | 覆盖映射、目标映射、问题级别、修补建议与重新检查对象均可交给应用。 |
| 修补与交付 | 优先修补影响发布的内容，保留原来源与版本，重新验收受影响部分。范围仍有关键缺失就返回 `needs_source`。 | `outcome: ok` 只返回可供应用独立校验的合格计划。 |

长书可在 AgentArts 编排子工作流，或由应用 worker 把章节分析产物明确收齐后给编排流程。给每组稳定 `section_id`，汇编核对齐套再处理。平台支持[嵌套子工作流](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0330.html)。[变量聚合节点](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0085.html)在同一组取首个非空值，多章并行时应使用可核对的清单或显式收集步骤。

### 输出规则

- 结构按样例的 `nodes, routes, coverage, practice_alignment, reuse, verification`。需要前置的边标出后续哪个目标要用及理由。教材中的例证和附录可落在节点参考区，并在覆盖表标出。确定错误要更正并说明来源。记号差异、过时内容和学科争议保留适用情境与原教材口径。额外补漏注明出处。
- 过关题给目标、实际任务、题面、参考解和可接受的变体。只在该任务需要的程度扩展。复用旧节点时对照目标、深度和条件，报告 `reuse` 中哪些旧节点保留及新增哪些教材来源。新增要求另备内容。
- 限时模式优先用户给出的实际考核资料。可按课程、学校、教材版本查补公开资料并记录匹配程度。资料不足时说明采用教材基础。少于 7 天返回 `study_checklist` 和可立即学习的来源。公开视频可根据可核查的标题、分集和时长推荐，说明依据。系统学习默认全书范围，核心路线内部可查、保持相对稳定。
- 回归用例至少有一节未覆盖、有环前置、题需未教公式、轻微教材口径差异、漏图/缺页和旧节点目标不等价。分别确认修补、待补件或可发布结论。真实教材数据的质量用[验收表](05-acceptance.md)记录。

教学验收依照[教材主线的开放检查](../node-concept-draft.md#教材主线的开放检查)。课程映射与教学/测验对齐可参考[卡内基梅隆大学课程映射](https://www.cmu.edu/teaching/assessment/assessprogram/levels/levels3.html)和[目标与测验对齐指南](https://www.cmu.edu/teaching/assessment/basics/alignment.html)。

## T3 · 支线返回续学工作流

1. 读应用已恢复的焦点、节点学习目标、出发位置和原问题。按相关性从本次支线摘出一两段可直接支持当前教学的原文。支线涉及超出主线的主题时先回到原目标，必要时简短提示联系。
2. 以用户刚学会的具体内容接原问题的一步。输出 `reply_md`、`used_refs` 和适合当前目标的 `next_step_md`。每条关键事实用传入的准确版本做出处。支线没有可用成果时可以沿原断点继续并说明还要弄清什么。
3. 同一主线问题先用「缓存还没到期」，再用「已到期，取得新结果」。说明和下一步应随支线实际成果改变，并各自指向真正使用的记录。再测空支线、无关内容、引用失效和并发焦点切换。焦点恢复由应用完成，工作流负责教学。

## T4 · 其余 teacher 与 keeper 行为

按[工具契约](06-agent-tools.md)为每种教学任务选用工具并写提示词。验收查什么、怎样复核以及最终引用是否和当前教学相关。应用后端负责数据与工具调用本身。

### 目标式规划与预测

- 给一个可观察的近期产出，先查可靠的原始公开资料。保存标题、出处、章节、查阅时间和相关摘录。来源有限时清楚说明，并可请求用户补充。示例材料从 [样例来源](examples.json) 起步。
- 提前把连续几个小节点准备到可开始学，给理由、目标、引入、材料、活动和先后依赖。Teacher 给出会优先推荐哪个以及为什么，交给用户确认。教材主线正常答疑始终围绕当前目标。有直接帮助的课外技巧可短提用法及条件，把深入原理留给用户自主展开。
- 支线根据目标变化识别是否已成为独立课程。当前问题解决后仍希望系统学新方向时，给新图建议和出发链接。按用户选择决定教材入口还是目标入口。

### 主动核查与学习证据

- 主线阅读后可邀请用户用自己的话说明一个关键点。优先利用已有表达。只接收完成的一段和用户明确指定的版本进行核查。核查时尽量覆盖条件、结论、概念和推导步骤，可同时返回多类问题。反馈给引文、等级、简短提示和按需展开的内容，解释深度受用户水平与本节点目标约束。
- 首轮反馈指出下一步要检查什么。用户按提示修订后可确认纠正，另用预备过关题或新题看能否独立解释或应用。Teacher 能主动邀请，也可响应用户请求。已有独立证据就接着教。跨节点证据精确引用实际展示过的目标。
- 反复求助时优先找出卡点。如果必要前置未完成且被跳过，用足够证据给应用复核。已做完前置之后依然困惑，可以换例子、拆步骤、练习和鼓励，给出实际展现的能力。

### 检索、关联和撤回

- Teacher 可直接查当前问题需要的材料。按出处回读原文后用于解释。Keeper 适合独立发现有用但非必要的旧知识、前置关系或类比。提示只说明联系，带可打开的历史版本。只共享词语或缺乏依据时选择无结果。
- 回应完成后 teacher 可复核当时出现的提示。关系不适合就提撤回。用户已打开并可能被错误关系误导时，补可读更正。应用按原焦点与提示 ID 变更呈现，原笔记及证据都可继续读取。

### 自测和复盘

- 在备课时按目标准备题面、参考解和独立检查，开考后从本场真实题面再做一次，优先检查用户报告的题。只向正在作答的用户发规则回应或核实后的勘误。剩余时间不足时给出作废理由并留存已作答内容。
- 交卷后根据冻结答卷找最早卡住的关键步骤，必要时用短题辨别能否回忆或应用。用新情境补练。回查他处教材时考后互动仍属于自测节点。

## 教学交付件

- 两段可发布的流程结构、可复用的输入输出样例、一次应用调用的结果以及可复跑方法。教学用例与实际调用采用同一字段结构。
- 教材规划的节→节点和题→目标对照、来源、未通过示例与修复后的结果。至少展示一次连续跨节编排和独立核查。
- 一个用不同支线成果对照续学的记录。另提供其余 teacher/keeper 行为的短样例与预期返回，由前后端按共用契约接入。
