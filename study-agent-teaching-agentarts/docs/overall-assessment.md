# 学习辅助 Harness 整体项目评估

日期：2026-11-17。对象：团队经过本次讨论汇合后的完整学习产品方向。性质：助手评审意见；不是最终需求、效果验证结论或获奖预测。

## 1. 总体判断

值得继续做。当前已具备较连贯的学习过程设计，价值主张比仅以笔记续写或图谱展示为中心更明确；创新尚未被证明，范围与质量要求都较高。

适合继续打磨为参赛和长期维护的产品，但没有依据声称已具备明显获奖优势。继续增加功能并非当前最优先事项，核心工作是确定哪些功能彼此驱动、共同构成最有价值的能力。

## 2. 当前已认可的产品主张

让用户能够组织和重组自己的学习过程，在主线、兴趣支线与跨学科联系之间自由移动，同时持续获得适合自己的教学辅助。用户已明确认可这一主张。

资料丰富但缺少清楚路线的自学，是已有目标场景。以上记录产品定位意图，不代表创新性已被验证，也不提前确定节点与 merge 的具体语义。

## 3. 已经形成的功能关系

目标及资料 → 初步学习路线 → teacher 导学 → 用户表达理解 → 综合检查 → 分别记录推进与掌握情况 → 提出后续灰色候选 → teacher 推荐并说明理由 → 用户选择。

keeper 的历史内容、跨课程联系与来源可支持当前理解和后续建议；用户自主探索、返回及预留 merge 让路线保留弹性。具体节点与 merge 定义仍待讨论。

上述关系比功能并列更有意义，但实际是否产生学习收益仍待后续验证，当前不要求立刻安排实验。

## 4. 值得保留的优势

- 场景较明确：资料已经存在，自学者仍缺少组织、理解反馈及连续学习支持。
- 独立表达后再诊断，与用户希望自己形成理解的目标一致。
- 系统提出建议，用户选择是否采纳，保持学习者对探索方向的控制。
- 双维进度避免把学过直接等同于学会。
- 个人历史和跨课程联系为长期使用提供积累价值，前提是这些记录实际改善后续帮助。
- 图式学习过程可呈现学习路线与探索，但图本身不构成教学价值证明。

## 5. 当前主要风险

### 竞争差异尚未确立

[RemNote Guided Learn](https://help.remnote.com/en/articles/15724936-guided-learn-mode) 已覆盖资料生成计划、测验及掌握度追踪；[Roadmap AI](https://roadmap.sh/ai) 提供个性化路线生成入口；[PersonaPath](https://arxiv.org/abs/2609.18861) 研究目标、学习状态与前置知识驱动的路径规划。

这些先例说明不能把规划、导师、进度、知识图分别作为全新能力。未实测竞品全部行为，不能断言它们缺少本项目某项组合。

可争取的差异是：用户自己的理解表达和长期历史，怎样改变当前反馈与后续候选；以及用户探索后，学习过程怎样保持连续。这仍是待打磨和验证的创新主张。

### 范围较大

资料组织、导学内容、诊断质量、学习状态、路线建议、图操作和持久化都需要投入。若各模块均追求完整，容易出现界面和功能齐全、学习体验却缺乏突出优势的结果。

其中尤其困难的是可靠地判断理解、给出适合的解释、组织合适的后续建议，而不只是显示页面和连线。

### 学习者可能承担过多规划负担

保留选择权有价值，但目标用户本就可能不知道该学什么。大量灰色候选若缺少明确理由，会把规划工作重新交给学习者。系统需要提出有帮助的建议，同时保留不采纳的自由；具体数量和界面以后再议。

用户已采纳的高层改进：系统展示候选，由 teacher 推荐节点，最终决策仍交给用户。推荐质量和实际减负效果尚未验证。

### 未定义能力不能提前算作创新成果

branch／merge 的意义和节点内容仍待定义，目前只能视为方向；teacher／keeper 的命名和 agent 数量也不能直接作为创新论证。

## 6. 理解反馈对自由学习的支持

“理解反馈能够影响后续学习建议”是助手提出的候选教学支持机制，不能写成团队已经接受的唯一产品中心。用户当前更看重节点化的自由学习方式。

其意义是让 teacher 根据用户实际表达改变解释、回顾及推荐理由，从而辅助用户在图中选择和探索；不自动改写路线，也不要求所有探索必须先通过检查。

它能让导学、检查、记录和节点预测形成前后关系，与自适应学习已有研究重合，不单独宣称首创。具体解释见 [节点化学习与反馈机制](feedback-and-node-learning.md)。

## 7. 一个可继续思考的创新候选

在 teacher 充分核查并发现关键误解后，利用历史学习关系提示它可能影响过哪些旧内容，给用户选择回看；由此把当前诊断和长期 keeper 记忆连接起来。

这是助手提出的可选方向，不加入当前必做清单。它不意味着自动判定所有关联内容错误、自动降低掌握度或强制重学；范围与可行性尚未讨论。

## 8. 当前阶段的建议

功能范围先保持稳定，围绕产品中心、模块关系和两个角色的职责形成一份清楚的产品定义。阅读呈现、节点内容、merge、诊断程度、篇幅及具体实验仍按用户要求后议。
