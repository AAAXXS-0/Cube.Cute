# 学习辅助 Harness 设计进度盘点

日期：2026-11-19。基于当前讨论和工作区材料。完成度针对文档所描述的设计，不是排期、开发进度或参赛评分预测。下一步顺序与赛事展示重点属于建议。

## 1. 现在在哪一步

已经从需求发散走到「产品大纲成形，准备细化规则」。若分为「定位与范围 → 核心体验与职责 → 产品规则与首版范围 → 工程方案与验收 → 实现与试用」，目前前两步大体完成，第三步刚起。以一份能开工的**产品设计**为目标，粗估过半，约五到六成；以可演示、可提交的作品为目标，当前工作区仍以文档为主，不能把这个比例换算成项目交付进度。

## 2. 已有的决定与还缺的设计

| 方面 | 已经说清 | 还没细化 |
|---|---|---|
| 定位与范围 | 面向本科生和自由学习者，先做电脑网页；有教材和无固定路线两种自学；比赛适配不绑定长期底座 | 首版必做哪些、哪些先做窄、哪些后置；比赛版与长期版的工程边界 |
| 导入与节点 | teacher 按教材备主线节点，支持无前置依赖的部分并行；自主支线先写先问；预测节点是用户可选的建议 | 教材目录如何转成学习单元、什么粒度适合、如何判断前置、导入后什么时候可开始学；实际读到什么 |
| 节点内学习与评价 | 用户先读、可问可写；表达完成后检查；反馈适配用户水平；推进程度和掌握程度分开 | 哪些活动构成一次有效的学习、何时可以完成节点并继续、哪些表达和练习能作为掌握证据、练习／考试和进度怎么关联 |
| 学习路线 | 用户主动开支线；回主线可自动接续；手动 merge 可引用成果或在无主线时新建阶段整理；系统学习新主题另开树并留来路 | 对话分支与学习节点的关系；各操作的界面和结果边界；并行节点的进度计算；预测的触发、范围和备课深度 |
| 记忆与协作 | 持久保存学习记录，teacher 可按需读；直接有用于讲解的由 teacher 引用，选读关联归 keeper，可在答复后撤回不合适提示 | 哪些历史记录进入检索，怎样保留教材出处与用户笔记版本，如何判断关联是否成立；具体检索、编排、时延与失败处理 |
| 工程与交付 | 已有赛题理解和电脑网页、长期可维护的方向 | 划定首版工作量，定核心数据与页面、AgentArts 负责的真实流程、演示、验收、试用与后续验证 |

当前缺的关键规则是：**进了一个学习节点后，用户怎样把它学成一段可以结束、也可以续上的经历。** 连完成节点和掌握知识的最低依据都未说清，进度、自动 merge 和 keeper 复用就容易依赖含糊的聊天摘要。建议先明确「读、表达或练习、反馈、结束或继续」各有什么产出，再讨论进度条怎么算；不要求每个节点都强制考试，也不提前定反馈字数或分数线。

## 3. 工程创新与赛事表达

用户强调不必追求单独的论文式创新点，工程实践也能体现创新。建议把差异说在一个可运行的行为上：**学习路线可以改变，已形成的理解、被纠正的表达和没解开的疑问仍能找回，并用于新位置的学习。** 在有教材的场景里是开支线后接得回、引用得了；在无固定路线的场景里是从预测向外探，再由用户把成果收拢成可回看的阶段整理。teacher／keeper 的分工让旧内容在合适时机参与这个过程。

[RemNote Guided Learn](https://help.remnote.com/en/articles/15724936-guided-learn-mode) 已有导入生成学习计划、问答和练习；[Sensecape](https://sensecape.github.io/) 已探索非线性探索与分层整理。单个功能、界面上的图或 agent 数量不足以说明差异。这里的机会是把已确认规则做成可感知的连续体验；尚无成品或学习效果证据，不宣称首创或已具备获奖优势。

赛事要求与项目创新分开看。按 2026-11-17 已查阅的[华为 ICT 创新赛赛题二页面](https://e.huawei.com/cn/talent/#/ict/innovation-details?zoneCode=027425&zoneId=98269700&compId=85132021&divisionName=%E4%B8%AD%E5%9B%BD%E5%8C%BA&type=C002&isCollectGender=N&enrollmentDeadline=2026-11-30%2023%3A59%3A59)，作品需要实际使用 AgentArts 构建、编排和部署智能体并可演示。可选工程路线是让 [AgentArts 工作流](https://support.huaweicloud.com/helppanel-agentarts/agentarts_20_0004.html)负责一段确实会影响学习体验的导学、核查或检索协作，产品自己掌握节点、学习记录和来路。仅切模型接口不足以推定满足要求；平台集成与赛事验收尚未实做，提交前复核官方要求。

## 4. 建议推进顺序

1. 先补单节点学习规则和双维进度的含义，写清用户与 teacher 各做什么、留下什么。
2. 回到路径与记忆，细化打开、离开、返回、引用和合并时哪些内容被带过去；用短场景检查冲突。
3. 定首版范围、平台分工和可观察的验收条件，再据此走完整流程、做工程设计和实现。

比赛版应尽早验证 AgentArts 能跑一段核心链路，此技术小验证可与产品规则设计并行。具体演示课程、界面和学习成效实验不在本轮决定。
