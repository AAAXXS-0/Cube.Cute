# 共同起步

## 要交付的用户流程

三个人按一名前端、两位偏后端来开工。前端负责整个电脑网页体验。应用后端负责数据、状态和接口。产品与教学负责人负责 teacher、keeper 的教学行为及两段 AgentArts 工作流。

| 流程 | 首版交付结果 |
| --- | --- |
| 有教材 | 确认目标和范围，上传并后台备课。全书通过检查后一次性开放。用户可任选主线起点，回查教材和核心路线，写理解、收反馈、开支线与返回，再做计时自测和复盘。 |
| 只有目标 | 确认目标，teacher 查资料并先备好近期里程碑和连续几个可学的候选。用户自行采纳、学习、记录和整理。后来选定教材时，可在原图中增加全书主线并沿用目标与要求等价的旧节点。 |
| 长期使用 | 可从答复、反馈、合并、关联提示或复盘回到当时的原文和版本。用户能导出笔记 Markdown。应用内状态可在切换教学服务后继续使用。 |
| 比赛接入 | 教材编排与验收、支线返回续学均真实部署在 AgentArts 并由应用调用。以完成度选择演示主故事，两个入口保留各自的产品验收。 |

## 联调采用的首版默认值

以下是交接时补定的工程默认值。各负责人可在第一轮开工时调整自己负责的实现。跨角色变更同步共用契约、样例和验收。

| 项目 | 默认安排 |
| --- | --- |
| 工程与本地开发 | Node.js 24、TypeScript，网页用 React 与 Vite，应用 API 用 Fastify，数据库用 PostgreSQL。同仓库的 `web/`、`server/`、`agentarts/` 分别维护，服务端运行可独立恢复的后台任务。本地联调可用固定样例用户，应用数据按 learner ID 隔离。团队先约定实际启动命令后补到 README。 |
| 材料与阅读 | 首版可导入带文字层的 PDF、Markdown、纯文本。节点里展示阅读引入、精确出处、学习要求和练习，原教材可另开查看。扫描页、缺图、公式抽取失真需要以明确状态指出，必要内容缺失时请求补件。用户输入用打字，Markdown 渲染与导出有统一约定。 |
| 完成一段表达 | 提供「这段写完了」保存成固定版本。Teacher 从这种事件中自主挑选适合核查的段落。用户也可在自由对话里点名请 teacher 核查任一已保存版本。普通输入与草稿自动保存持续可用。 |
| 候选与里程碑 | 从目标开始时先准备两三个有内容的候选深度用于联调，数量可配置。里程碑用可观察产出描述，teacher 可凭作品建议已达成，用户确认或调整。 |
| 进度与掌握 | 路线进度显示完成节点数与该路线的必计节点数。可选自测和阶段整理保留自己的状态。无主线显示里程碑。掌握区显示具体目标、证据及独立程度。 |
| 上下文与响应 | 用轮询观察后台任务与迟到的 keeper 提示，流式答复由前后端约定后补。对话按焦点和记录版本接续，首版以学习分支和显式引用覆盖分叉学习用例。 |
| 教学服务 | 应用使用可配置的教学 provider 和公开资料查询工具。比赛配置把教材编排与支线续学两个操作路由到 AgentArts，其他操作使用可替换的模型接入。联调可用本地样例，各操作可以分别切换真实服务。 |

竞赛演示优先把真实学习动作、来源回查和两段已部署流程做完整。独立桌面安装、手写与图片理解、编辑器公式补全、Obsidian 导入同步、视频逐段分析在后续阶段单独安排。与 Markdown 联动从单向导出开始。

## 目录和接口由谁负责

| 文件范围 | 主责 | 需要交接给谁 |
| --- | --- | --- |
| `web/` | 前端 | 与后端对齐请求及状态，与教学确认人能否读懂引用、建议和检查。 |
| `server/` | 应用后端 | 提供本地样例、API、数据库迁移及工作流适配，与前端和教学各接通一次。 |
| `agentarts/` | 产品与教学 | 提供流程结构、提示词、输入输出样例、已发布部署调用参数说明和失败示例。平台所需的凭据通过环境配置交给后端。 |
| 共用契约和联调数据 | 后端维护结构，产品与教学维护教学含义，前端维护可见状态 | 原则上一个定义只在一个地方更新。改字段、事件归属或验收结果时同步受影响的任务书。 |

应用端负责生成正式 ID、操作校验、事务和发布。模型与外部工作流接受明确的快照，只能产出建议或待验证结果。教材编排和支线返回的 adapter 边界保持稳定，开发样例和已部署流程都走同一套校验。

## 第一轮怎样并行

1. **F1**。前端读[示例 JSON](examples.json)给网页加本地数据层，先把导入状态、阅读台、浏览 B、在 A 开 S、从 S 返回 A 和出处面板串起来。
2. **B1**。后端建立数据库表、种子数据和基本 HTTP 处理，实现 A/B/S 共用样例所需的节点、焦点、事件、原始记录版本。做好配置与迁移，向前端交接真实 base URL。
3. **T1**。教学负责人按同一教材和两份不同支线成果，在 AgentArts 验证两段核心流程。提供严格 JSON、引用 ID 和真实部署回执，后端先接 mock 再换同契约 provider。
4. 首次会合只验收两个薄切面。A/B/S 在真实 API 上有明确的焦点与可回查的引用。小册编排结果通过校验并生成能点击的图。随后并行完成按目标开局与自测，再接合并、补教材、跨学科提示和边界场景。

未知的学习效果、复杂教材的准确率、实际耗时和运行资源留给实现后的试用。每项实现提交时提供可重跑的小样例、观察到的结果和仍待打通的接口。
