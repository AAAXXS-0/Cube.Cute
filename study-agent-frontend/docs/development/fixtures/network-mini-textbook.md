# 一次网页访问中的查询和请求

自编联调用短教材，版本 1。范围包括以下三个小节。

## DNS 查询和记录

用户访问一个域名时，客户端可以向递归解析器请求地址记录。解析器可能用可用的缓存作答，也可能向其他 DNS 服务器查询。权威服务器负责提供相应 DNS 区域的数据。以下问题只考虑一个解析器的缓存和一条 A 记录。

假设权威服务器把域名地址改为新地址，有的查询暂时仍得到旧地址。先区分「权威数据已改」与「递归解析器当前用哪个答案」。权威数据更新后，其他系统里已有的缓存可能继续使用。

## 缓存与 TTL

DNS 资源记录的 TTL 以秒表示，可用于限定该记录的一般缓存寿命。教材示例把解析器取得记录的时刻记为起点，忽略刷新、预取和到期后服务旧数据等扩展策略。这个简化例子里的到期时刻为「取得时刻 + 当时的 TTL」。

假设解析器在 10:00:00 取得旧地址，TTL 为 120 秒。权威数据在 10:00:30 更新。10:01:00 时原缓存仍可用，10:02:00 时其有效期结束。之后的重新查询若成功取得更新后的权威数据，便可使用新地址。

## HTTP 请求与响应

这一节假设客户端已经可以向服务器发送消息。客户端发送 HTTP 请求，服务器处理后返回 HTTP 响应。请求方法之一是 GET，可请求目标资源当前的表示。响应状态码描述处理结果，例如 200 通常表示请求成功。

在一份样例日志里，先记有「GET /index.html」，随后显示「200」。前一条记录表达客户端所请求的资源，后一条记录是服务器返回的结果的一部分。
