# 第三轮：teacher 导学与可返回的横向探索

日期：2026-11-17。状态：继续讨论产品行为，尚未进入实现或具体验证安排。

## 1. 用户本轮明确的选择

- 产品主要体验为跟随 teacher 按大纲学习。
- 用户可以主动横向展开、偏离主线，并能随时返回；teacher 在主线及支线过程中持续提供辅助。
- 节点树除了课程知识组织，也承担主线与横向探索路径的作用。
- 横向展开可能激发兴趣，容纳新的灵感及追问；这是产品意图，尚非已验证的效果。
- keeper 只需说明跨知识联系并展示旧内容；用户可以就该联系与 teacher 自由交流。
- 不采纳第二轮提出的关联卡回忆／比较题候选，不默认给每条关联附上活动。
- 先把设计聊通，具体课程及效果验证暂后置。

上述关联交互的选择不等于取消最初提出的课程考试、自测功能，后者仍待单独讨论。

## 2. 当前可整理出的产品流程

这是对已有需求的整理，未定部分仍需讨论：

1. 导入资料、确定学习目标，teacher 提出大纲。
2. 用户进入一个大纲节点，teacher 带领学习；节点中的主要活动尚未确定。
3. 出现疑问或兴趣时，用户可以留在当前节点继续问，也可以进入支线。具体分支规则尚未确定。
4. teacher 在支线上继续提供讲解、对话与表达后的检查；keeper 可提供相关旧内容。
5. 用户决定返回时，恢复主线的具体学习问题和待继续内容。

## 3. 候选节点含义

候选设计，尚未获用户确认：一个节点承载围绕明确主题或问题的一段学习过程，里面可以包含多轮对话、资料、笔记及检查记录。

需要分清：

- 知识点是可以被多次学习、多门课程引用的内容对象。
- 学习节点记录某次围绕该内容或问题发生的学习过程。
- 课程大纲组织计划中的学习节点；兴趣支线可从计划之外产生。

由此，一个问题可以先在节点内继续交流，只有需要独立保留和导航时再形成支线。是否这样处理，仍待用户回答。

## 4. 横向探索与返回的候选行为

用于讨论的虚构过程，不作为实际验证课程：

- 主线当前问题：一个递归过程为什么会终止。
- 用户产生兴趣：递归和数学归纳法有什么联系。
- 进入支线后 teacher 与用户讨论，keeper 可以展示另一门课程中的归纳法旧笔记。
- 用户返回时，teacher 先恢复“递归为什么会终止”的原问题，再衔接有帮助的支线内容。

返回需要保留原问题、停留位置、未解决之处及支线留下的相关表达。仅打开旧页面可能不足以恢复学习上下文。

仍待讨论：teacher 是否在返回时做极短回顾、支线是否影响主线进度、何时允许把支线变成新的主目标。

## 5. 本轮需要保留的反驳

- 兴趣可以是横向探索的正当设计目标，不必要求每条支线直接服务考试。
- 开放探索还需要明确的方向和返回体验；一张不断长大的树不自动保证用户知道自己正在学什么。
- 每条消息都拆成节点会使导航碎片化；按主题或问题聚合是候选改进，具体规则未定。
- 不能把所有支线所得内容直接算成主线掌握，也不能只因偏离计划就否定探索的价值。具体进度表达留待后续。

## 6. 补充检索

[Google Research 的 Learn Your Way 介绍，2025-09-16](https://research.google/blog/learn-your-way-reimagining-textbooks-with-generative-ai/) 描述了基于教材生成分节内容、测验、讲解及层次化思维图，并依据用户年级和兴趣调整例子。可借鉴资料与教学呈现的组织方式；该介绍没有证实本项目设想的主线／支线返回机制。

[Gruber、Gelman 与 Ranganath，2014](https://www.cell.com/article/S0896627314008046/pdf) 的论文摘要报告，好奇状态与其研究任务中的即时及一天后记忆收益相关。它提供兴趣与学习关系的机制启发，不证明自由分支必然改善课程学习。本轮依据检索到的原论文摘要，全文直接抓取受限。

以上是设计参考，不据此发起当前阶段的实验或要求用户提供具体验证材料。
