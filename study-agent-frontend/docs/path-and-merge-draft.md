# 路径与 merge 讨论稿

更新：2026-11-22。保留用户提出的路径用途，并补充 agent 与节点配合的上下文方案。具体实现仍待讨论。

## 1. 用户提出的用途

1. **把支线成果带回原处。** 切回主线时，teacher 仍应知道用户在支线做过什么、真正弄清了什么、还有什么没弄清。数据库能保留记录，但用户认为仅凭可查询的历史不能完全解决接续问题。主线、支线与对话如何共享上下文，见第 5 节的讨论方案。
2. **让并行的学习路径有汇合处。** 导入教材时，没有前置依赖的章节可以并行，用户先学更感兴趣的，剩余章节按目标再考虑；例如先学第 1、3 章再接续第 6 章。用户倾向有主线时保留已备好的节点，怀疑仅为体现合并而另建节点是否有帮助。
3. **在无主线时收拢分散的学习。** 用户认为自动接回支线与手动带入成果都可以叫 merge。没有预先备好的承接点时，主动把几个节点中互相关联的内容汇到一个新节点，可以避免沿着候选一直越学越散。

## 2. 自动与手动 merge

| 需求 | 用户实际得到什么 |
|---|---|
| 自动 merge | 从支线回到原来的学习位置时，teacher 按当前目标接上相关进展，例如已检查过的推导、仍没解决的问题。是否需要一个可见的临时提示不在此轮决定。 |
| 并行主线汇合 | 章节顺序由真实依赖决定。几个主题可分别推进；已有综合节点按它实际用到的前置知识接续。各章节保留自己的进度，不为进入下一章而制造中间节点。 |
| 手动 merge | 用户选要带入的学习成果，让目标节点以后能明确使用和回看，例如自己的解释、推导、解题办法或尚待解决的问题。可以汇到已有节点；无主线时也可将几个来源合成有独立用途的新节点。保留出处，原始记录继续可查。 |

数据库解决“当时发生过什么可查”，本次返回的来源解决“应该从哪段接上”，当前节点的目标决定“哪部分值得带入”。两种 merge 都接回有用内容，区别在触发方式和结果：建议自动 merge 服务于本次教学接续，手动 merge 让用户选中的成果长期在目标节点里有一个明确位置。可以保留回到原文的引用；被纠正的说法和已确认的理解要能分清。查到旧记录、选中成果或学完某一章，都不直接等于掌握。

用用户的例子：如果「导数」和「圆锥曲线」在这份大纲所设的范围内互不依赖，就可以先学任一项。若已有的「用导数研究椭圆的切线」节点确实要用两者，学习路径可自然在它汇合；空间几何若与该目标无关，不妨继续留在自己的线路上。若第 6 章只需要第 1 章的知识，就无需等待第 3 章。章节编号与学完几章都不能代替依赖判断。

有教材的例子：用户在支线推清了「隐式求导为什么能求出椭圆的切线斜率」，把自己推导中经核查的一段引用进已有的综合节点。下次教到那里，teacher 可以沿着用户自己的写法继续。也可以从几条路径挑成果带入同一节点，不用把已经编排好的课程另造一份。

## 3. 无主线时把几条线收成一个节点

例：学习者想弄懂网页打开的过程，用分散资料分别学了「域名解析」「建立连接」「HTTP 请求和响应」。可以主动把三处理解汇到「输入网址后，浏览器到拿到页面之间发生了什么」。teacher 帮忙理清每段材料解释的是哪一步、哪些地方还接不上；原节点和记录仍可按出处回看。若发现「连接已建立」和「页面已经返回」仍容易混淆，就有了一个具体的后续问题。

建议以同一个问题为中心，收拢相关学习成果，留出尚未解决的部分。只想把几份笔记放在一起找时，分组或链接就足够。用户已确认新节点可以只做阶段整理；之后想继续，可在节点里问 teacher 下一步，必要时沿用已有的灰色预测候选，由用户选择。原有范围边界仍适用：如果目标已变成另一门课程，则建议另开树并留原节点链接。

## 4. 相邻先例

- [ALEKS 的 Ready to Learn](https://www.aleks.com/about_aleks/index)让学习者在当前适合进入的主题中选择，说明按条件提供多条可选路径已有先例；不能据此推定系统能准确从任何教材提取章节依赖，也不照搬其主题开放规则。
- [ContextBranch](https://arxiv.org/html/2512.13914v1#S4.SS3.SSS4)区分切回一段聊天和挑重点带进另一段聊天。可借鉴只回接有用内容的思路；它研究的是编程对话，不能据此推断学习效果，也不需要照搬消息复制方式。
- [Sensecape](https://sensecape.github.io/)把非线性探索与多层次的信息整理放在同一个工具中。可借鉴探索与收拢反复切换的思路；这里的新节点围绕学习者的问题与已有学习记录，效果仍待验证。

## 5. 节点和 agent 的上下文

用户要求重新设计 agent 与学习图的配合，并已确认**学习焦点**。同一时刻由一个节点作为当前学习焦点。用户可以浏览其他节点，也可以就其中的内容引用、提问或请 teacher 核查。Teacher 按用户所指的位置查阅相应材料，把这次学习事件记录在当时的焦点节点，并关联材料的实际出处。

用户确认开始计时综合自测后，焦点锁定在自测节点，直到这一场结束。整份答卷归于该节点，答题中独立展示的能力可用于对应学习目标的掌握判断。[计时综合自测](product-outline.md#大纲里的计时综合自测)

交卷后解除焦点锁定。Teacher 讲卷时可以带用户去看相关知识节点并补学，再回到试卷。复盘与穿插的补学都以自测节点为焦点，考后问答与复测归在该节点，引用仍指向实际来源。[交卷后讲题与复测](product-outline.md#交卷后讲题与复测)

上下文组装建议。每次 teacher 回答或检查时，应用提供焦点节点、当下的问题和明确引用的材料。焦点提供课程范围、学习目标以及该节点上的近期进展。用户指到其他节点上的内容时，按出处加载该内容。同一个学习问题可以借用多个节点的材料，围绕当下的事取用近期原话、草稿和未解问题。

| 用户的动作 | 建议带给 teacher 的信息 |
|---|---|
| 在同一题上追问或要求核查 | 用正在讨论的几轮原话和确切的题目、草稿或被指到的步骤。例如「上面第二步」先沿对话和草稿的引用找原句。 |
| 在 A 学习，打开 B 并询问其中一段内容 | 从 B 取回用户所指的内容，在 A 的学习语境中作答。这次交流记在 A，引用可指回 B。 |
| 主动开支线，再返回 | 开支线时把学习焦点切到支线，带上原题、出发的位置和开支线的原因。沿来路返回时恢复出发时的焦点和位置，由 teacher 自动接回对原题有用的理解、检查结果或卡点。 |
| 去另一节点开始学习 | 将焦点设为新节点，从其目标和此前在那里学到的位置开始。若用户说「这里和我刚才写的那条式子有关」，再回查被提到的原文。 |
| 下次回到没做完的题 | 先恢复上次做到的步骤和未解问题，再按需打开当时的推导或反馈。 |

历史摘要可帮助定位旧记录。用到具体推导、教材条件或核查结论时，沿出处取回原文，并辨明它是用户当时的写法、修订后的写法还是 teacher 的反馈。若前文指代有多个合理对象，问清指的是哪一处。[长期学习记录与出处](teacher-keeper-retrieval-draft.md#5-长期学习记录与出处) · [Anthropic 的上下文工程说明](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

Teacher 查阅与当前教学有用的内容。Keeper 可利用旧记录寻找关联，提供能回查的内容和联系。两者可使用同一份学习记录，根据各自要做的事取用不同内容。[检索与配合讨论稿](teacher-keeper-retrieval-draft.md)
