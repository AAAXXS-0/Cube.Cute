# 节点化自由学习与理解反馈

日期：2026-11-17。用途：解释两个设计层面的关系。示例为假设情境，不是最终节点定义、交互规格或验证材料。

## 1. 当前用户主张与已采纳改进

- 当前主要产品主张是节点化的学习进度与学习方式，支持用户自主分支、合并和跨学科关联。
- 系统展示灰色预测候选，teacher 推荐节点并说明理由，用户最终决定是否采纳、采纳哪些以及怎样选择。
- teacher 推荐不等于替用户决策，理解检查也不等于强制学习关卡。
- “理解反馈影响后续学习”由助手提出，当前用于解释可如何支持上述体验，不替代用户的核心主张。

## 2. 这项机制的含义

用户表达出的理解差异，可以转化成 teacher 后续解释、回顾和节点推荐的差异。反馈因此影响接下来的帮助，而不只是在当前段落旁保留一个错误标记。

直白地说，就是根据用户当前理解来选择怎么帮助。知识资料、关系和个人学习记录提供可调用内容；用户这次的表达补充了当前理解的线索，teacher 据此选择解释、回顾或推荐方式。因此它会运用知识库，但范围还包括根据当前学习情况调整帮助。若将个人学习记录也纳入广义知识库，两者的联系会更紧密。

例如，同样围绕二分查找学习：

| 可见的学习表现 | teacher 需要关注的方向 | 可能提出的建议 |
|---|---|---|
| 认为任何数组都能通过丢弃一半来找到目标 | 是否理解有序性与排除另一半的依据 | 回顾有序性和排除规则 |
| 能解释前提，但草稿中反复出现区间边界问题 | 是否理解搜索区间的含义及如何保持它 | 学习或练习边界处理 |
| 所见解释与练习较稳定，也能处理边界 | 是否可以继续当前目标内的后续内容 | 下一学习主题或应用练习 |

这些是候选判断，teacher 仍需结合上下文，不凭一句话就确定掌握程度。用户可以采纳推荐，也可以继续当前主题或主动探索其他候选。

## 3. 可能影响哪些帮助

- 解释：根据当前理解选择更适合的表述、例子或回顾内容，仍遵守学习水平与主线范围。
- 推荐：说明为什么这个候选值得现在考虑，包括观察到的困难或已有基础。
- 历史调用：keeper 提供有关旧内容，由 teacher 判断怎样用于当前讨论；用户主动发起的跨学科追问也可得到支持。
- 记录：保留本次可见表现，为后续理解判断提供上下文。具体掌握度计算和证据规则仍未决定。

## 4. 与节点化自由学习的关系

节点化、branch／merge、跨学科联系描述用户组织和改变学习路径的方式；理解反馈描述 teacher 怎样根据这个人的情况提供帮助。两者可以相互支持，无需在当前阶段将其中之一排除。

用户即使理解尚不完整，也仍保留主动探索权。系统可以指出推荐理由和前置关系，不擅自替用户加入必修内容。

## 5. 对创新主张的评审

节点化自由学习可以成为产品的主要竞争方向，但尚不能仅据操作名称证明新颖性：

- [Graphologue](https://arxiv.org/abs/2305.11473) 已探索通过交互图开展非线性 LLM 问答。
- [Sensecape](https://sensecape.github.io/) 已探索空间组织与多层抽象支持的 LLM 信息探索。
- [Traverse](https://traverse.link/) 将思维图、关联笔记及复习结合。

这些来源不证明它们具有用户设想的完整学习节点、branch／merge 及跨课程进度体系。本轮未实测其全部功能，不能据此判定本项目完全重复或已形成独有优势。

可继续论证的方向是：节点是否真正组织个人学习过程，探索能否被持续接续，不同课程的学习内容能否被有效调动，以及 teacher／keeper 是否在自由选择中持续提供帮助。具体行为和 merge 定义仍按用户要求后议。

相关研究 [PersonaPath](https://arxiv.org/abs/2609.18861) 已将目标、学习状态与前置知识用于路径规划评估，因此理解状态参与推荐本身也有先例；本项目需在具体场景与交互机制上建立差异。
