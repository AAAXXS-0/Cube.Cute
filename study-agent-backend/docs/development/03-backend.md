# 应用后端开发任务书

你负责应用 API、数据库、文件、后台任务和两段工作流接入，并牵头端到端联调。产品规则和外部工作流返回按[共用开发契约](01-contract.md)处理。以[联调数据](examples.json)交付固定种子，再换真实 provider。

## B1 · 数据、焦点、版本与基础 API

1. 建 API 进程、数据库连接、迁移和样例种子。建议按图与路线、会话与记录、准备任务、考试四个业务模块组织。提供本地启动和无外部凭据的样例装载命令。学习者身份从服务端会话确定，本地固定用户用于联调。
2. 学习图、节点和路线用稳定 ID。正文和关系用发布版本，记录保存可回查的版本。资料索引用来源及版本指向原文件、页或小节，源文件与抽取片段入持久化存储。当前焦点用每用户一行保存图、节点、断点、版本和锁。节点完成与进度按学习者当前的路线计算。
3. 实现读工作台、按版本取引用、显式切焦、当前断点保存、写入已保存记录和 A/B/S 开支线返回。写操作事务内校验预期焦点版本，必要时用行锁。幂等键的已处理结果和写入事件一起提交。恢复支线来源时带齐 checkpoint，当场产生可重取的续学任务。
4. 请求进入服务端时存焦点版本、节点版本、当时的提问和引用的原始记录版本。异步任务完成后按这些值写回。只在新焦点仍符合事先条件时允许带有切焦决定的动作。Teacher 可给推荐或核查结果，正式状态由应用校验。
5. 提供 `mock` 与真实工作流适配器的共用输入输出验证入口。初期以 `workflows.resume_branch.request` 和两个对照案例接通返回故事。与前端联调后再打开 AgentArts 模式。

| 持久关系 | 优先保证的一致性 |
| --- | --- |
| 图、节点与路线版本 | 路线引用同一图中的已发布节点。完成状态按节点和学习者唯一。切换版本不影响旧引用。 |
| 原始来源、节点与记录版本 | 声明的版本和定位可回查。合并、评估和续学引用冻结后的版本。日常草稿可有最新工作副本，一旦用于反馈、考试或对外引用即保留当时快照。 |
| 分支与返回事件 | 创建 S 与切焦一同提交。来源含 A 的节点版本、问题与断点。返回事件按当次幂等键唯一。 |
| 正式答卷、题目和复盘 | 开始时固定已确认规则和题组版本。交卷快照、勘误时间线、已存答案和考后教学分别可查。 |
| 建议、证据与学习记录 | 建议有状态、适用的节点版本和依据。证据指具体目标与表现记录。撤回建议保留处理记录。 |

## B2 · 资料、后台编排与原图补教材

- 上传按文件存原件、摘要和解析信息，校验类型和大小。PDF 首版提取文字及页号，可把页数字与印刷页标分开。Markdown/文本保留小节和行范围。开卷条件下按规定资料集合提供源文件。PDF 阅读与提取可参考 [PDF.js 的页文字 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html#getTextContent)。
- 导入任务使用数据库队列或团队约定的耐久队列，工作记录可见阶段与进度。用领取期限或等价机制回收被中断的任务。工作流请求有唯一 ID、重试上限、超时及错误类别。收到结果时验证版本与发布前置条件，网络重试复用同一输入。多 worker 如采用 PostgreSQL 队列，可用锁领取防止重复抢占。见 [PostgreSQL SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html)。
- 目录分组处理，保存章节原件引用、章节分析结果和必要的跨组背景。在最终组装后检查指定范围覆盖、前置 DAG、真实来源与练习目标映射。结构有效但教学未通过的方案留在任务里报告问题，旧发布版本可继续用。缺关键原文返回待补件及具体范围。确认合格时一次发布节点、关系及路线数据。
- 单图初次路线和已有图补教材区分结果。后者返回采用建议，含目标与要求的映射、旧节点重用、需要新增的节点和新来源。应用校验基准路线/节点版本，用户确认后事务发布。重用稳定 ID，保存旧节点及路线版本。限时清单及复习路线依明确的可用天数和资料类型返回。
- 从目标开局保存用户目标、来源、建议里程碑与候选。保存候选之间前置或连续的解释。采纳动作幂等并返回正式 ID。目标学习可有并行支线、跨图来源链接和手动聚合，单独保持引用的归属。

## B3 · 上下文、检索、反馈与导出

- 按[工具契约](06-agent-tools.md)实现两个共用阅读工具及 teacher 的公开资料工具。把任务的学习者、焦点和考试状态传给应用处理器。用现有版本读取和来源存储登记本次引用，用 `tool_cases` 联调无命中、失效和考试限制。
- 给 teacher 组装窄上下文。优先当前目标及节点版本、当前问题或提交记录、在场显式引用、最近相关事件和可回查的旧证据。允许按问题检索应用里明确相关的条目，初版从 SQL 范围、关键词和对象关系开始，检索服务可替换。
- Keeper 独立找历史资料与跨图相关记录。可与 teacher 的任务并行，迟到的提示追加到所捕获的节点。保留关系理由、引用版本、产生时的焦点版本、可见状态。Teacher 回应后可申请撤回不合适的提示，应用验证归属与目标提示后做状态变化。提示呈现不依赖两个模型顺次对话。
- 对于核查、讲解、阶段整理、弱点与复习建议，验证模型输出结构和引用白名单。已写完表达可按相同版本只核查一次，主动重查产生新的反馈版本。将完成、反馈解决、独立证据按各自事件入库。强制复习见契约中的必要条件，使用真实前置关系与实际提出过的困难，持有自测锁时不执行。
- 手动 merge 接受同一用户可读的具体来源版本。保留选中的原文列表，索引摘要与目标，默认焦点留在原地。跨图查看和教材补编排以授权检查和版本解析统一处理。
- 导出一图或一节点的用户笔记、已保存表达与必要出处。用 UTF-8、稳定文件名、标题分段、当前版本及日期。学习记录以团队约定标注反馈、精确引用或有用的来源名，文件可在 Markdown 编辑器和 Obsidian 中打开。排除凭据、内部模型提示和本场未到解锁条件的试题。

## B4 · 考试事务与后台复核

1. 预览查询只返回范围、预计时长和规则。题库及解析与一般节点读 API 分开。允许明确的规则协商，经复核后在开始前更新预览版本。若图中有已考旧场次，只能从其独立复盘链接读当时题目。
2. `start` 在一个事务中验证同意和当前版本，建立该场快照及服务端截止时间，切焦并锁定。对同一学习者保持最多一场进行中的自测，并为重试返回同场。客户端能从场次读 API 收到真正题面。
3. 答题、交卷和到期使用服务端时间及可顺序提交的事务。刷新仍按原定时间。后台作业到点交卷，读取或写入场次时也可补做过期终态。正式答案以截止或确认交卷前已保存的版本为准。相同写入可重放，已提交场次冻结原答卷。解锁时焦点仍归考试节点。
4. 开考后排独立验题任务，优先处理报告题。只发布校验通过的事实勘误。保存原题、修订、发布时刻和已作答版本。剩余时间不足以按新题作答时作废该题，沿用本场截止并保留答题过程。
5. 考后任务用冻结答卷和实际题面版本生成可逐步展开的解释与补练。复盘浏览相关资料时保持焦点，相关证据链接所展示的目标。严格区分考试问答、规则响应、背景验题和考后教学的读取与写入。

## B5 · 联调与提交

- 维护 [共用契约](01-contract.md)、[样例](examples.json)与实际 API 的对应关系。提供环境模板、迁移和样例命令、队列启动方式、二种 provider 模式与故障定位方法。
- 先用 F1/T1 执行 A/B/S 和短教材发布，再接目标路线、自测及复盘。浏览、焦点、任务状态、引用及考试锁都从真实 API 验收。
- 两段工作流均接好后保留应用 job ID、输入版本、调用部署标识、耗时、结果校验和引用读取结果。回执宜脱敏，实际部署凭据由运行配置读入。
- 提交前执行[验收表](05-acceptance.md)对应状态、重试、引用和自测边界。应用时间、模型耗时和用户页面等到结果的时间分别记录。
