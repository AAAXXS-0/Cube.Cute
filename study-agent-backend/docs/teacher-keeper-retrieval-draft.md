# teacher／keeper 检索与配合讨论稿

更新：2026-11-22。呈现原则及答复后的撤回权已获用户认可。记录留存与回查是用户委托助手制定的首版规则，检索与编排仍属实现建议。

## 1. 找得到、讲得清、现在用得上

| 判断 | 建议归属 | 例子 |
|---|---|---|
| 哪些记录可能相关 | 共用检索工具 | 在当前用户的资料中找到带有「反向向量」或同义说法的笔记，并返回可回查的出处。 |
| 两处有什么具体联系 | keeper 可在整理记录或主动发现时判断 | 线代笔记里的「非零向量乘 −1 会反向」可以帮助理解梯度下降更新式里的负号。有出处和关系说明才构成一条可用的关联。 |
| 现在该怎么用 | teacher 在当前教学中判断 | 若用户正问为什么要减去梯度，就引用这条旧笔记；若正在理解学习率，就不把它硬塞进解释。 |

直接用于讲解的由 teacher 引用出处；可以串知识但不必插进讲解的，由 keeper 提供简短选读提示。仅有关键词重合的结果不用主动出现。keeper 的提示只解释联系并展示旧内容，不自动开支线或布置练习。

## 2. teacher 怎样直接查

teacher 能自己发起查找，与 keeper 共用查阅工具。查阅已知教材段落、节点来路或此次返回的支线时，直接沿原有引用取原文；不知道出处时，按当前节点目标及用户的问题搜索。通常先找本节点、课程或明确关联的记录；需要调动旧知识时才扩到其他课程。术语可用关键词匹配，用户换一种说法时可用语义匹配，不在本轮决定具体算法与阈值。

一次返回少量候选：原文片段、可点回的位置、来源是教材／用户笔记／teacher 反馈；有可解释的关系时再附一句关系及依据。如果带到的是曾被纠正的笔记，尽量同时能回查对应反馈。没找到就返回空结果；这只说明这次没找到相关记录，不能据此断定用户没学过。

实际用途：按教材原文讲当前范围内的内容；判断某个旧误解是否有已纠正的表达可参考；自动 merge 时沿已知来路接上支线，而不用用户重述。存过一条解释不等于用户已掌握，查询用于找证据和个性化解释，不直接改学习进度。

## 3. 回答与主动提示分开走

- **teacher 当场需要资料：** 直接调用检索工具，根据结果引用、舍弃或继续问清楚。在普通教学中不需要先让 keeper 用模型评一遍，再等 teacher 回消息讲哪条该展示。
- **keeper 主动发现：** 可在不阻塞当前回答的情况下，用当前节点目标和旧记录发现可解释的联系。结果如果需要 teacher 用，可作为候选交给它；值得选读的关联可以独立提示，无需事先逐条等 teacher 批准。同一条已被 teacher 引用的内容不重复提示。

两个角色是职责划分。独立模型间的调用只有在结果确实需要另一轮判断时才有价值：每加一段必须等待的推理或远程请求，都会让回答多等这一段；tool 调用本身也有开销。暂不承诺固定耗时。实现时可用同一批问题比较首字出现时间与引用质量，判断多一层筛选是否值得。

[Anthropic 的编排说明](https://www.anthropic.com/research/building-effective-agents)将顺序模型调用描述为用额外延迟换取任务表现的取舍。[AgentArts 的知识检索节点](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0086.html)支持关键词、语义和混合检索，可作为比赛版读取教材的候选；用户学习记录、来源链接及 merge 语义由产品掌握，不据此锁定长期存储或推定赛事验收已满足。

## 4. 回复后复核与撤回

用户同意 keeper 自行提示，并要求 teacher 在完成用户请求以后可以检查已出现的条目，撤回不合适的条目。两者即使用同一个基模，收到的上下文和提示词仍可能不同；也可以分别换模型。这项纠正能力不依赖模型选择，不作为正文答复的前置步骤。

助手建议撤回只作用于这次呈现。例如，笔记内容正确但不适合当前问题，就收起这次提示；如果 keeper 把类比错说成前置条件，且用户已打开或基于它提问，应让用户知道错在哪里。原始笔记、用户留下的内容和学习进度不随提示撤回而改变。复核时带上与该条目对应的学习位置和解释依据，避免用后来切换到的节点来判断前一处的提示；具体触发与呈现留待后议。

[微软的人机交互指南](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/)强调在系统出错时让纠正与恢复容易。这里是否需要可见更正，取决于这条提示有没有影响用户的理解，是本项目的设计建议。

## 5. 长期学习记录与出处

| 内容 | 首版留存规则 |
|---|---|
| 用户的笔记、草稿、问题和对话 | 保留用户可见的对话原文和已保存的笔记、草稿。继续编辑时保存当前稿，正式核查、作答或引用时留住当时用的版本。 |
| 学习成果和评价 | 保留节点完成记录、里程碑成果、手动 merge 的内容及来路、反馈与被检查的原文。正式自测按本次保存题面、已发勘误、作答条件、提交的答卷和考后复盘。 |
| 教材、引用和路线 | 保留可回查的教材原文、版次和对应位置。采用公开资料时保存出处、查阅时间和实际用到的片段。保存用户采纳的教材路线和之后的修订，记录当时使用的学习目标及材料。 |

每次学习事件归到发生时的焦点节点。引用指到实际用的资料、笔记或作答的版本及具体片段。打开教材引用时定位到相应教材版本的章、节、页或图表。打开旧反馈时，先呈现当时核查的那版推导与被指出的文字。用户修改后可再核查，让新反馈与新稿对应。可参考 W3C 对引用片段、资源当时的版本和修订关系的表达。[W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/) · [W3C PROV-DM](https://www.w3.org/TR/prov-dm/#term-Revision)

日常关联优先找笔记、已检查的作答、未解问题和阶段成果。续学或明确引用时，再沿原引用读取相应的对话和原稿。摘要可用来定位，判断掌握时回查当时实际提供的证据。若有多个可能的对应段落，请用户指出其中一处。

例如，用户在旧路线里提交过一道推导，随后采纳了调整教材顺序的建议。回看答卷时能找到当时看到的题面和当时的解释。在修订后的路线学习时，teacher 可引用其中已经独立展现的能力。
